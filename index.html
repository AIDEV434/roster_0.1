About ROSTER

v0.3 · Apache-2.0

What this catches.

ROSTER is a local-first forensic console for business email compromise — the impersonation scam that has cost organizations more than ransomware in recent years.

Commercial BEC tools route your email through someone else's cloud and run proprietary detection on it. ROSTER runs in your browser. Detection rules are readable. Trust roster lives in localStorage. Nothing about your email is logged or transmitted — when RDAP is enabled, only the sender domain is queried against rdap.org.

Active Detection Rules

ROSTER-001Display-name impersonation
ROSTER-002Lookalike sender domain (typosquats)
ROSTER-003Punycode / non-ASCII (homograph)
ROSTER-004Reply-To divergence on roster sender
ROSTER-005Missing auth headers (DMARC required)
ROSTER-006SPF / DKIM / DMARC fail on roster sender
ROSTER-007First-contact + financial language
RDAP-101Domain registered < 30 days ago
RDAP-102Domain registered < 7 days ago [Critical]
RDAP-103Recent registrar change / update activity
RDAP-104Suspicious / known-abused registrar
RDAP-105Missing or sparse RDAP metadata
RDAP-106No DNSSEC

Threat model.

Defends Against

  • Display-name spoofing from arbitrary domains
  • Lookalike and typosquatted sender domains
  • IDN / Punycode homograph attacks
  • Reply-To redirects on roster senders
  • SPF / DKIM / DMARC bypass attempts
  • First-contact senders using financial-fraud language
  • Freshly registered phishing infrastructure (RDAP enabled)

Does Not Defend Against

  • Compromised legitimate vendor mailboxes — every rule passes
  • Malicious attachments / URLs (use sandbox in parallel)
  • Deepfake voice / video referenced inside emails
  • Session token theft / account takeover

Privacy

Everything runs locally. Trust roster is stored in localStorage and never uploaded. When RDAP intel is enabled, the sender domain only is sent to rdap.org — no email body, no recipient, no headers. To stay fully offline, leave RDAP disabled.

Reality Check

This is v0.3. Detection logic should be peer-reviewed before reliance in production. Open issues and PRs on GitHub.
